# Автоматизовані UI- та API-тести

Набір тестів на Playwright і TypeScript для SauceDemo під демонстраційним користувачем `standard_user` і [Restful Booker](https://restful-booker.herokuapp.com/apidoc/).

## Встановлення та запуск

Потрібні Node.js 20 або новіший і доступ до інтернету. Виконуйте команди з кореня репозиторію.

```bash
npm ci
npx playwright install chromium
npm run typecheck
npm test
```

На Linux для встановлення Chromium із системними залежностями запустіть `npx playwright install --with-deps chromium`.

Playwright завантажує публічні демонстраційні облікові дані з `.env.example`. Для локального перевизначення значень скопіюйте цей файл у `.env` або задайте змінні середовища `E2E_USERNAME` і `E2E_PASSWORD` для UI чи `BOOKER_USERNAME` і `BOOKER_PASSWORD` для API.

```bash
npm run test:ui                  # Лише UI-тести
npm run test-ui                  # UI-тести з відкритим Chromium
npm run test:api                 # Лише API-тести, без браузера
npm test -- --ui                 # Інтерфейс Playwright
npm test -- --grep @main         # Основні сценарії UI та API
npm test -- --grep @edge         # Негативні та граничні сценарії
npx playwright show-report       # Перегляд HTML-звіту
```

## Покриття UI

| Група | Сценарії |
| --- | --- |
| Основні (7) | Успішний логін, видимість карток каталогу з очікуваними назвами й цінами, сортування за назвою Z–A зі збереженням цін, сортування за ціною від більшої до меншої, додавання двох товарів у кошик, видалення одного з двох товарів, оформлення замовлення на два товари з перевіркою підсумку та підтвердження |
| Негативні та граничні (3) | Порожня форма логіну, неправильний пароль, видалення останнього товару з кошика |

Кожен тест запускається в окремому контексті браузера. Фікстура виконує вхід для тестів каталогу, кошика й чекауту. Page Objects задають XPath-селектори через `locator(...)` і використовують атрибути `data-test`. Очікувані товари та ціни задані в `tests/data/catalog.ts`.

## Покриття API

| Група | Сценарії |
| --- | --- |
| Основний (1) | Отримання токена, створення бронювання, перевірка збережених даних, зміна, повторне читання, видалення й перевірка відповіді `404` |
| Негативні (2) | Неправильний пароль без видачі токена, спроба змінити бронювання без токена з перевіркою незмінності даних |

API-тести працюють із власними бронюваннями з унікальними іменами. Фікстура прибирає створені записи, які залишилися після тесту.

## Що свідомо не автоматизовано

- **UI.** Інші браузери, мобільні розміри екрана, інші демо-користувачі, сортування за ціною від меншої до більшої та повний набір перевірок полів чекауту. Автоматизований чекаут перевіряє оформлення замовлення з товарами в кошику.
- **API.** Фільтрація списку бронювань, формати відповіді крім JSON і повний набір перевірок полів бронювання. Негативні тести зосереджені на авторизації та захисті оновлення.

## Знайдені баги

Ці баги відтворені в SauceDemo. Очікувані результати ґрунтуються на правилах оформлення замовлень.

### UI-01. Можна оформити замовлення з порожнім кошиком

Середовище — SauceDemo, Chromium, користувач `standard_user`.

**Кроки**

1. Увійти під `standard_user` у новій сесії.
2. Відкрити кошик і переконатися, що в ньому немає товарів.
3. Натиснути **Checkout** і заповнити поля даними `Alex`, `Tester`, `01001`.
4. Натиснути **Continue**, а потім **Finish**.

**Очікуваний результат.** Оформлення заблоковано, доки в кошику немає хоча б одного товару.

**Фактичний результат.** На сторінці підсумку відображається `Total: $0.00`. Після натискання **Finish** відкривається сторінка з підтвердженням `Thank you for your order!`.

### UI-02. Чекаут приймає ім’я з одних пробілів

Середовище — SauceDemo, Chromium, користувач `standard_user`.

**Кроки**

1. Увійти під `standard_user`, додати **Sauce Labs Backpack** у кошик і натиснути **Checkout**.
2. У полі **First Name** ввести три пробіли.
3. У поля **Last Name** та **Zip/Postal Code** ввести `Tester` і `1234`.
4. Натиснути **Continue**.

**Очікуваний результат.** Форма залишається відкритою та повідомляє, що ім’я обов’язкове.

**Фактичний результат.** Форма приймає пробіли й переходить на сторінку підсумку замовлення.

### UI-03. Пряме посилання показує підтвердження до оформлення замовлення

Середовище — SauceDemo, Chromium, користувач `standard_user`.

**Кроки**

1. Увійти під `standard_user` у новій сесії.
2. Додати **Sauce Labs Backpack** у кошик.
3. З каталогу відкрити в адресному рядку [сторінку підтвердження](https://www.saucedemo.com/checkout-complete.html).
4. Перевірити повідомлення на сторінці й відкрити кошик.

**Очікуваний результат.** Сторінка показує підтвердження лише після завершення чекауту.

**Фактичний результат.** Сторінка одразу показує `Thank you for your order!`. Лічильник кошика залишається `1`, а доданий товар досі є в кошику.

## GitHub Actions

Workflow запускає перевірку типів, UI- та API-тести на кожен push і для pull request до `main` або `master`.

HTML-звіт доступний у GitHub у розділі **Actions → Playwright Tests → запуск → Artifacts → playwright-report**. Звіт зберігається 30 днів і завантажується також у разі падіння тестів, якщо Playwright встиг його сформувати.
